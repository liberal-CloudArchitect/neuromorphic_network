# CR-015：把“读出增强写入 + 预测误差门控”的工作记忆接入完整模块化网络（T-Gate）

**本 CR 是供用户审阅的草案。** 在用户批准之前，不实现任何模块、不改动任何代码、不运行任何 seed。配套的 Gate 级协议草案见 `docs/p6_implementation_spec.md`（status: DRAFT）。

## 触发证据（T track，均为 exploratory，不构成 Gate 证据）

| 来源 | 结论 |
|---|---|
| T1（`docs/transfer/T1-report.md`） | 预测误差（结果 surprise）门控工作记忆写入：无提示规则切换后的恢复 +10.9pp，学会的 seed 从 5/10 增至 10/10；但仍比 shared GRU 差 2.9pp |
| T1b（`docs/transfer/T1b-report.md`） | 候选写入改为来自读出增强后的表示（读—改—写）并保留门控后，与 shared GRU 非劣（−0.3pp / −0.05pp），差距缩小 96–99%；写入结构决定上限，门控决定可靠性；二者缺一不可 |
| T1c（`docs/transfer/T1c-report.md`） | 三个情境交错、单情境静默切换时，T1b 的工作记忆比 GRU 恢复低 3.6pp、OOD 低 2.2pp（非劣不成立）；槽结构对未切换情境的干扰更小，但被切换情境的更新更差。事后推测：surprise 门控加在所有槽上，不按情境寻址 |
| T2（`docs/transfer/T2-report.md`） | 与本 CR 无直接关系（读出/防遗忘），但提示：主网络模块上的局部规则可以得到与回放相当的结果 |
| P5（CR-009） | 主线当前把预测 surprise 用作路由调制；T track 的结果提示它更应门控记忆写入 |

## 拟批准的变更

1. **新模块 `working_memory.v2`**（`neuromorphic.modules`，新模块 ID 与 state version `working-state-v2`；`working_memory.v1` 不改）：
   - 读出与 v1 相同：a_t = softmax(M_{t−1} q(r_t)/√d)，e_t = r_t + P·read_t；
   - 候选写入来自读出增强后的表示：c_t = tanh(W_c e_t + b)；
   - 更新门加入 detached 的预测误差：g_t = σ(W_g r_t + b + s_t·w)，w 每槽一个、初值 2.0；
   - 其余（4 个槽 × 32 维、read-before-write、episode reset、逐 item TBPTT）与 v1 相同。
2. **新组合器 `ModularBrainNetworkV4`**：在 V3 的图上把 `working_memory.v1` 换成 v2，并把 `predictive_adapter.v3` 已经计算的每步 surprise（P5 冻结的 detached `log1p` SmoothL1 forecast error）同时送入 v2 的更新门。路由与其他模块不变。
3. **主线任务新增 `uncued-rule-switch`**：把 T1 的无提示切换任务改写为主线任务接口（作答后有结果反馈、无切换 cue），与 AR、DRS、SmallGraph 一起构成四任务套件；全部使用新的 P6 namespace 与独立 split seeds（建议 train 31101、validation 32201、test 33301、OOD 34401、analysis 35501），不复用 P1–P5 与 T track 的样本。
4. **新协议 `p6-protocol-v1` 与 Gate `GATE-6-WM`**，阶段与主线相同：qualification → pilot → mechanism → full，每一阶段通过只授权进入下一阶段。

## 保持项

- P1–P5 的模块、任务、配置、协议、锁与历史结果全部不变，`p5-protocol-v2` 不受影响。
- `neuromorphic.transfer` 与 `neuromorphic.fly` 不被主线导入；v2 在主线中按主线抽象重新实现，并用单元测试逐元素核对它与 T1b 的 `enr_gate` 方程一致。
- T track 结果只作为本 CR 的动机，不作为 `GATE-6-WM` 的证据。

## 需要用户决定的问题

0. **是否先做 T1d。** T1c 显示全局的 surprise 门控在多情境下不如 GRU。建议在接入完整网络之前，先在 T track 上检验按内容寻址的门控（g_t = σ(W_g r_t + b) ⊙ (1 + s_t·a_t)，a_t 为本步读出注意力），再决定 `working_memory.v2` 用哪一种门控。若用户希望直接推进 T-Gate，草案按 T1b 的全局门控编写，并把“多情境任务”列为 full 阶段的风险。
1. **是否依赖 P5 的结局。** P5-09 的 mechanism 尚未在 clean SHA 上运行。选项：(a) 等 P5 mechanism 结束后再启动；(b) 以 V3 为底座直接启动（T-Gate 只裁决工作记忆，不裁决路由）；(c) 以 P4 的 V2 为底座，避开尚未验证的 v3 路由。草案按 (b) 编写，因为 V4 与 V3 只差工作记忆，mechanism 的对照都在同一底座上，路由的成败不影响对工作记忆的因果裁决。
2. **surprise 的来源。** 主线原生的是预测器的 forecast error；T1/T1b 验证的是“结果 surprise”（|反馈 − 自己的作答概率|）。在 uncued-rule-switch 中，预测器以所选动作为条件预测反馈观察，其误差在反馈步上应近似结果 surprise，但这尚未验证。草案以 forecast error 为主，并在 qualification 中加入一项检查：反馈步上 forecast error 与结果 surprise 的相关 ≥ 0.5，否则停止并回报。
3. **full 阶段的主张。** T1b 只显示与 GRU 持平。草案把 full 阶段对 shared GRU / Transformer 的主检验定为非劣（界值 2pp），superiority 只作次要检验；若希望沿用 `GATE-NN-MVP-v2` 的 superiority 门槛，需要明确改动。
4. **seed 数。** 主线惯例是 `[17, 29, 43]` 三个 seed；T track 用 10 个 seed 才得到窄的 CI。草案保留主线的三个 seed，并在报告中列出所有 seed；也可以改为五个 seed（预算约增加 2/3）。
5. **算力与设备。** mechanism 与 full 的预算按主线的 MPS/CUDA 通道估计（见协议草案第 6 节）；需要用户确认可用设备与墙钟上限。

## 风险

- 预测器的 forecast error 在 AR/SmallGraph 上不是“结果”信号，门控可能在这些任务上无谓地打开写入；mechanism 设有逐任务非退化检查（≤ 2pp）。
- 工作记忆是路由的可选专家之一；若路由很少把反馈步送入工作记忆，门控就没有作用。qualification 中检查 uncued-rule-switch 的反馈步进入工作记忆的比例，并在协议中冻结语义覆盖（建议与 DRS 一样强制 100%）。
- T1c 已显示多情境下工作记忆不如 GRU；主线的 AR（多对 key-value）与 SmallGraph 需要多个独立变量，full 阶段的非劣检验可能因此失败。
