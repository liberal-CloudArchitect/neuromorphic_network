# CR-012：消除 P5 AULC、checkpoint 与伪辅助损失歧义

## 触发证据

在正式三 seed mechanism 启动前的实现审计发现：

1. `macro_aulc` 实际是 validation 分数的算术平均，没有使用 analysis split、真实 step 轴或固定训练预算；不同 early-stop 长度可能产生不可比结果。
2. mechanism 虽跟踪 validation best/stale，但正式评估与冻结 checkpoint 控制读取最后 checkpoint，而不是最佳 validation checkpoint。
3. `episodic.separation` 基于任务提供的固定、不重复 one-hot key；`router.communication_cost` 基于离散 executed mask。两项在 P5 中不提供忠实的可训练梯度，不得用非零权重制造“优化了该机制”的表象。
4. DRS dual-route 使用逐 step Python 循环并通过 `Tensor.item()` 读取设备标量，造成不必要的 host synchronization。

这些问题尚未产生 P5 正式结果，因此不得用旧实现运行正式 Gate，也不得沿用 v1 qualification、pilot 或 mechanism-qualification 锁。

## 批准修正

- P5 全链协议升级为 `p5-protocol-v2`；CR-009～CR-011 与所有历史 P3/P4 结果保持不变。
- mechanism 每个 validation interval 同时记录 held-out analysis macro point `(global_step, score)`；validation 只负责 early stop 和 checkpoint 选择，analysis 不参与选择。
- `analysis_macro_aulc` 必须调用共享 `normalized_aulc`，在每个 retrained cell 的固定 `max_steps` 预算上积分。early stop 后按最后 analysis point 延伸到冻结预算。
- validation 改善时保存独立 `best.pt`；正式评估与所有同 seed frozen-checkpoint 控制必须加载 full 的 `best.pt`。
- checkpoint 升级为 `p5-checkpoint-v6`，持久化严格递增、有限的 analysis curve；v5 checkpoint 不得在 v2 协议下恢复。
- 正式 Gate 在 bootstrap 前独立复算每个 retrained summary 的 AULC；缺少 analysis curve、预算、best-checkpoint 标记或复算不一致时直接拒绝裁决。
- dual fraction 以 DRS eligible tokens 为分母；capacity drops 从正式 summary 进入 Gate。二者都不得用全任务分母或固定占位值弱化约束。
- P5 中 `episodic.separation` 与 `router.communication_cost` 保留为诊断量，optimizer 权重固定为 `0`。未来若引入 learnable key 或忠实 cost surrogate，必须再开协议变更。
- DRS dual-route 改为张量化的逐 step 分段排名；必须保持每 step `floor(valid * 0.25)`、stable tie-break、语义覆盖和 zero-drop 不变量。

## 保持项

- CR-011 的八 cell/seed 矩阵、seeds、数据量、最大 updates、48 小时预算、五项 Holm family、效应门槛和最坏 task/seed 约束均不改变。
- `predictive_adapter.v3`、`sparse_router.v3` 的科学假说与行为路径不在本 CR 中增强；本修正不能被表述为预测因果收益。
- P1～P4 artifact、checkpoint 与 Gate 裁决不可回写。

## 反假阳性验收

- 旧实现必须在 fixed-budget AULC、analysis/validation 隔离、best-checkpoint 恢复和不可复算 summary 测试上失败。
- 新实现必须证明 early-stop 曲线与显式 plateau 曲线得到相同 fixed-budget AULC。
- 改变 P5 的两个诊断量不得改变 optimizer total；改变语义 CE 等可训练损失必须改变 total。
- 路由测试禁止通过 `Tensor.item()` 同步设备标量，并覆盖非整除 batch、padding 与多 step quota。
- 所有旧 SHA 锁在新协议下必须失效；只有 clean SHA 的 CPU、MPS/CUDA qualification、pilot、mechanism qualification 和 CI 能授权正式运行。
