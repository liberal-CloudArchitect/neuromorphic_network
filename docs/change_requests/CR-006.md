# CR-006：隔离 P4 加速器进程并持久化正式评估分区

## 触发证据

`p4-mechanism-e2b9c11a-20260814T141034Z` 在 48 小时内完成 10/24 cells，失败 0，随后于 SmallGraph live rollout 中触发 `RESOURCE_LIMIT`。同一 `predictor-off/s29` checkpoint 的 OOD scale rollout 在长生命周期 MPS 进程中耗时约 7.49 小时，而在新进程中完成 2,048 样本仅需约 61.3 秒；逐样本输出与冻结记录一致。

运行中采样显示主线程反复位于 `index_select_mps → MPSGraphCache::CreateCachedGraph`，进程物理占用峰值约 69.3 GB。正式 rollout 的活跃 row 数和 optional expert row 数随 step 改变，长进程因此积累大量形状特化的 MPSGraph。`torch.mps.empty_cache()` 只能释放 allocator 中未占用内存，不能清除进程级 MPSGraph cache。

## 批准变更

- suite 监督进程不执行模型前向或反向；MPS/CUDA 的每个训练 cell 使用独立 Python worker。
- 训练完成后退出 worker；评估重新从已校验的 `best.pt` 或 `checkpoint.pt` 加载模型。
- analysis/test/OOD 标准评估按 task 使用独立 worker；SmallGraph test 与三个 OOD live rollout 各使用独立 worker。
- 每个 worker 结果、逐样本记录和 telemetry 先写临时文件，再原子替换正式文件。
- cell 内新增版本化 evaluation registry。已完成分区只有在 config、matrix、protocol、checkpoint 和产物 checksum 全部一致时才跳过；损坏或缺失分区必须重跑。
- cell 完成前按冻结顺序合并所有分区，拒绝把不完整结果标记为 `COMPLETED`。
- `resource_limit` 继续是当前 run 的终态，不能伪装成可 resume；status 必须区分 `retryable_cells` 与需要新 run 的 `restart_required_cells`，并标记陈旧 heartbeat。
- 新增 Windows PowerShell 薄入口、CUDA 环境 smoke 和独立 CUDA qualification 配置。CUDA 运行目前只属于工程验证，不替代 P4 正式 MPS Gate。

## 科学协议保持项

本变更不修改模型、前向顺序、loss、optimizer、task version、split seed、正式 seed、样本、训练 step、early stop、干预、阈值、bootstrap、Holm family 或机制矩阵。SmallGraph active-row 与 expert slicing 的数值算法保持不变；进程边界不计入模型 MAC 或任务指标。

旧 run 永久保持 `RESOURCE_LIMIT / INCONCLUSIVE`。源码 SHA 改变后，必须从同一 clean SHA 重新执行 CI、MPS qualification、pilot 和 24-cell mechanism；不得拼接旧 cell。若未来将 CUDA 结果纳入科学 Gate，必须另行冻结设备、wheel、驱动、容差和成本口径。

## 验收条件

- CPU 上 worker checkpoint 加载、原子结果、checksum 拒绝与已完成阶段跳过测试通过。
- MPS qualification 通过，SmallGraph 四个 live rollout 均显示独立 worker 边界。
- 定向正式规模 MPS rollout 在重复 fresh-process 运行中时间和内存有界，逐样本结果满足既有容差。
- Windows RTX 4060 上 Python 3.12、PyTorch 2.12.1 CUDA smoke、CPU/CUDA 前后向和 P4 CUDA qualification 通过。
- `make check`、pre-commit、P1～P4 回归和 GitHub Actions CPU CI 通过。
