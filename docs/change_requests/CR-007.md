# CR-007：冻结 Windows CUDA pilot 选择通道

## 决策

在不改变 P4 模型、数据、优化器候选、seed、训练预算或选择规则的前提下，增加 `cuda-pilot` 控制器入口。该入口固定使用 Windows E 盘 `brain` 环境、RTX 4060、PyTorch `2.12.1+cu126` 与 CUDA runtime `12.6`，并使用 `artifacts/p4-cuda/` 下独立的 qualification/pilot 锁命名空间。

CUDA pilot 必须绑定 clean `HEAD == origin/main`、同 SHA 成功 CI 和同 SHA CUDA qualification。它只访问 train/validation，继续执行四个冻结 preset，每个 1,000 updates，并按 validation macro AULC、最终 loss、preset ID 的既定顺序选择。

## 边界

- CUDA pilot 不读取或覆盖 MPS qualification/pilot 锁。
- CUDA 与 MPS 的 pilot 结果不得直接混算；每个设备只授权自己的后续运行通道。
- 本 CR 只授权 pilot。CUDA mechanism/full 仍需单独冻结设备容差、成本口径和对应控制器配置。
- 既有 P4 科学阈值、P3 负结果及旧 `RESOURCE_LIMIT / INCONCLUSIVE` 运行保持不变。

## 验收

- `cuda-pilot` 配置解析为四个冻结 pilot cells，设备必须为 CUDA。
- 控制器只接受 `artifacts/p4-cuda/qualification-lock.json`，拒绝用 MPS 锁替代。
- Windows 后台 start/status/logs/resume/stop/verify 行为与 CUDA qualification 一致。
- 新 SHA 的 CPU CI 与 CUDA qualification 通过后方可启动。
