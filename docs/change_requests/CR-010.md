# CR-010：冻结 P5 恢复、观测、后台控制与 pilot

## Checkpoint-v5

- schema 固定为 `p5-checkpoint-v5`；保存 profile、candidate、matrix cursor、逐任务 cursor、best/stale、validation curve、梯度覆盖标记、配置/协议 hash、model、optimizer groups、RNG 和可选 NetworkState。
- 写入使用同目录临时文件与原子替换；加载在任何 live model/optimizer/RNG 变更前完成 ID、key、shape、dtype、finite、hash 与 staged deep-copy load 验证。
- pilot 在每 100 updates 保存；resume 只接受同 SHA、同 config hash、同 qualification/CI 锁。telemetry ledger 截断到 checkpoint cursor 后再继续，避免重复事件。

## Telemetry-v3

- 每个训练 update 最多一个 detached 聚合事件，记录 surprise、语义 required/executed、dual fraction、forecast/persistence error、scorer gradient norm 和 active/dense calls。
- `telemetry_enabled=false` 时不得调用 builder、CPU scalar 归约或 RNG；on/off loss、参数、optimizer 和验证指标必须等价。
- schema 继续包含人工计算模型免责声明，并禁止 atlas、Web、viewer、原始 tensor、数组和嵌套对象。

## 后台控制

- 入口：`scripts/p5_run.sh` 与 `scripts/p5_run.ps1`；支持 `start/status/logs/resume/stop/verify/record-ci`。
- qualification/pilot 的 MPS/CUDA 锁使用 `artifacts/p5-{device}/` 隔离；pilot 必须满足 clean `HEAD == origin/main`、同 SHA CI 和同设备 qualification lock。
- Windows 使用 detached process group 与 breakaway flag；macOS 使用 `nohup+caffeinate -ims`；两端均检查 Python/PyTorch、设备、磁盘和电源条件。

## Pilot 冻结

- 仅 seed 7、train/validation `8192/2048`、batch 64；禁止 analysis/test/OOD。
- 四候选各精确 1,000 updates，每 100 updates validation/checkpoint：
  - `preset-0`: lr `1e-4`、temporal `0.10`、semantic `0.01`；
  - `preset-1`: lr `3e-4`、temporal `0.10`、semantic `0.01`；
  - `preset-2`: lr `3e-4`、temporal `0.05`、semantic `0.01`；
  - `preset-3`: lr `3e-4`、temporal `0.10`、semantic `0.02`。
- weight decay `0.01`、dual budget weight `0.001`、dual fraction `0.25`、gradient clip `1.0` 固定。
- 候选必须满足 predictor/router 非零梯度且三个任务 validation forecast error 均低于 persistence；按 validation macro AULC 降序、final loss 升序、preset ID 升序选择。
- pilot 通过只授权设计三种子 mechanism；不授予科学收益或 network MVP 标签。
