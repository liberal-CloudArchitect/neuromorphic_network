# CR-014：把 F1 已确认的原理迁回主网络（T track）

## 触发证据

- CR-013 的 F1 阶段（`docs/fly/F1-summary.md`，27 轮）确认了若干原理；CR-013 规定，任何原理迁回主网络都必须经过新的 CR 与 protocol。
- 主线 P3–P5 的失败分析（见 CR-013 触发证据）指出，任务与机制不匹配：DRS 的规则切换有显式 cue，AR/DRS 的下一观测不依赖动作，SmallGraph 完全可观测；P4 中预测的因果作用被否证，P5 改为用 surprise 调制路由。F1 的结果提示了另一种用法：**预测误差应当门控“写入/学习”，而不是改写表示或路由**（F1b：门控可塑性在无提示反转下比纯关联学习高 20.5pp）。

## 批准范围

- 新增子包 `neuromorphic.transfer`，存放迁移实验所需的任务、模块变体与紧凑组合网络。它可以复用 `neuromorphic.modules` 与 `neuromorphic.tasks` 的公共组件，但**不得导入 `neuromorphic.fly`**；原理在主线中按主线的计算抽象重新实现。
- 不修改 P1–P5 的任何模块、任务、配置、协议或锁；`p5-protocol-v2` 不受影响。
- T track 的结果标记为 exploratory，不构成任何 `GATE-*` 证据。某项迁移在 T track 中得到支持后，若要进入主网络的正式 Gate，需要再提交一个 CR 并冻结 Gate 级协议（qualification → pilot → mechanism → full，与主线相同）。
- 每项迁移都必须满足主线已有的规则与 F1 的方法学教训：
  - 任务必须“非该机制不可”，并给出 oracle 上限；
  - 与参数量匹配的主基线（shared GRU）比较，并设置消融/置乱对照；
  - 协议在运行前冻结并提交；冻结前只允许在非正式 seed 上做冒烟测试或设计检查，改动在协议中披露；
  - 参数匹配的比较（各变体使用同一超参数网格与同一选择规则）；
  - 新的 task version 与独立的 split seeds，不复用 P1–P5 的样本。

## 迁移路线（按证据强度与对主线失败的针对性排序）

| ID | 原理（F1 证据） | 主网络中的对应位置 | 必需该机制的任务 |
|---|---|---|---|
| T1 | 预测误差门控更新（F1b：+20.5pp；P5 教训） | 工作记忆的更新门 | 新的**无提示**规则切换任务：规则静默改变，只能通过作答后的结果反馈发现 |
| T2 | 局部关联读出 + 部分冻结防遗忘（F1a：+30–43pp） | 读出/动作头 | 顺序多任务训练（主线的遗忘判据） |
| T3 | 环形吸引子保持状态 + 偏移旁路按速度更新（F1c-v4、F1o–F1s；可塑输入映射 F1i） | 新的连续状态模块 | 新的朝向/路径积分任务 |
| T4 | 广播式调制 + 突触级资格标签的巩固（F1k） | 情景记忆的巩固 | 干扰下的保持 |
| T5 | 二值稀疏扩展（约 5% k-WTA）用于多峰类别（F1a-v4） | 情景记忆的编码 | 多峰类别检索 |

每项迁移各有独立的 protocol（`docs/transfer/T*-protocol.md`）与报告。T1 先行。

## 科学边界

- 迁移的是计算原理，不是果蝇回路；主网络中的模块名称不因迁移而改称任何脑区。
- F1 的结论来自人工抽象（统一类型参数的速率模型、简化的可塑性规则）；迁移实验检验的是这些原理在主网络任务上是否带来收益，而不是验证 F1 本身。

## 附录 A：T 线结果（exploratory，不构成 Gate 证据）

本附录只记录结果，不改变本 CR 的状态（PROPOSED，待用户决定）。

| ID | 协议 / 报告 | 结果摘要 |
|---|---|---|
| T1 | `docs/transfer/T1-surprise-gate-protocol.md`（`6886143`）/ `docs/transfer/T1-report.md` | surprise 门控工作记忆写入：恢复准确率 +10.9pp（H1）、优于同信息输入 +3.9pp（H2）与打乱信号 +9.3pp（H3）；10/10 个 seed 学会（plain 5/10）。相对 shared GRU 仍差 2.9pp（H4 不支持） |
| T1b | `docs/transfer/T1b-write-structure-protocol.md`（`010b2bc`）/ `docs/transfer/T1b-report.md` | 写入结构 × 门控 2×2：候选写入来自读出增强后的表示时，门控工作记忆的恢复 +7.6pp（H1），与 shared GRU 非劣（H5 test 恢复 −0.3pp、H6 OOD 总体 −0.05pp，界值 2pp），差距缩小 96–99%；不优于 GRU（H4）。无门控时写入改进不能提高可靠性（H2 不支持，6/10 对 6/10），门控仍有独立贡献 +11.9pp（H3）。探针：记忆中恢复期规则可读性 0.81（GRU 0.82，current 写入 0.35–0.53）。事后：写入结构决定上限，门控决定可靠性 |
| T1c | `docs/transfer/T1c-multi-context-protocol.md`（`ad7f0fc`）/ `docs/transfer/T1c-report.md` | 三个情境各有规则、交错出现、单个情境静默切换：读出增强门控工作记忆比 shared GRU 恢复低 3.6pp、OOD 低 2.2pp（H1、H2 不支持，H4、H5 非劣不成立）；读出增强写入仍必要（H3 +6.9pp，`cur_gate` 0/10 学会）。槽结构对未切换情境的干扰更小（−0.4pp 对 −1.3pp），但切换后状态中可读出的新规则更少（0.37 对 0.52）。事后推测：surprise 门控不按情境寻址 |
| T1d | `docs/transfer/T1d-addressed-gate-protocol.md`（`440a0c8`）/ `docs/transfer/T1d-report.md` | surprise 偏置按读出注意力分配到槽上：多情境恢复只比全局门控高 1.2pp（H1 不支持），仍比 GRU 低 2.5pp、OOD 低 1.8pp（非劣不成立）；单情境与全局门控相同（H5、H6 非劣）。事后：寻址在 7/10 个 seed 上追平 GRU，3/10 学得慢 |
| T2 | `docs/transfer/T2-associative-readout-protocol.md`（`5ef3980`）/ `docs/transfer/T2-report.md` | 主网络模块上的局部关联读出（固定随机编码 + 20 倍稀疏扩展 + 只增强活跃单元 → 正确类）：类增量最终准确率 0.877 对 `gru_sgd` 0.205（H1），遗忘 0.048 对 0.992（H2）；学习规则、表示冻结、稀疏扩展各自有因果作用（H3–H5）；优于 EWC（H7）；与回放打平（0.877 对 0.879，H6 不支持、H8 非劣未通过）。在任务 1 上预训练再冻结的编码器不能推广到新类（0.458） |

对 T-Gate 的含义：若把 T1 的原理接入完整的模块化网络，工作记忆应同时采用读出增强的候选写入与预测误差门控，而不是只加门控；但 T1c 显示，在需要多个独立变量的任务上，全局的 surprise 门控使工作记忆不如 GRU，T1d 检验的按读出注意力寻址的门控没有可靠地修复这一点。T-Gate 的 CR 草案见 `docs/change_requests/CR-015.md`。
