# CR-004：保持 P4 科学协议不变并修复正式评估吞吐与日志可观测性

## 触发证据

首次正式机制运行 `p4-mechanism-fb53443a-20260722T160041Z` 在 24 小时墙钟上限处停止：24 个预注册 cell 中完成 15 个、失败 0 个、1 个标记 `RESOURCE_LIMIT`、8 个尚未开始。已完成产物的 62 个 checksum 全部有效，但缺少 seed 29 的最后一个控制和全部 seed 43，因而结论只能是 `RESOURCE_LIMIT / INCONCLUSIVE`。

剖析显示 SmallGraph 的正式 live rollout 以单样本 MPS 前向执行。每个 cell 固定评估 test 与三个 OOD 分布，共 8,192 个独立 episode；该实现使零训练步的控制 cell 仍耗时约 36～44 分钟，并成为矩阵墙钟的主要可消除开销。

## 批准变更

- 将 SmallGraph live rollout 改为固定批量执行；每个 batch row 仍对应一个独立图和独立 recurrent state。
- 提前终止的 row 不构造非法全 padding `TaskBatch`，只选择仍活跃的 row 前向，再把模块状态按原 row 位置函数式散射回批状态。
- episode、horizon、动作解释、成功率、路径超额、最优动作率、随机策略 chance、sample index、stratum 和输出顺序保持不变。
- 训练、validation 与 analysis batch 继续取冻结配置中的 `64`；SmallGraph live rollout 是无梯度、row 独立的正式推理评估，单独使用不超过 `1024` 的 batch（不足时取 split size）。样本量、split、seed、模型、checkpoint、优化器、阈值、统计 family 和 24 小时机制预算均不改变。
- runner 在 suite/cell 开始、checkpoint、完成、失败和资源停止时输出逐行 JSON 并立即 flush，使 `p4_run.sh logs` 能持续显示可解析进度。
- live rollout 在每个 batch 与 step 检查 deadline；耗尽预算时仍以 `P4ResourceLimit` 安全退出。

## 验收条件

- CPU 上 modular-v2 与 GRU 的逐样本标量/批量记录完全一致。
- MPS 上 batch `64/128/256/512/1024` 的逐样本记录完全一致；batch `1024` 必须通过内存安全和吞吐验证。
- 公共 `TaskBatch`、state ownership、episode reset 和 padding 契约不得放宽。
- 完整测试、类型检查、pre-commit、P4 CPU micro 与 clean-SHA MPS qualification 均通过。
- 代码 SHA 改变后必须重新生成同 SHA 的 CI、qualification 和 pilot lock；旧机制 run 不得原地恢复或被拼接进新 Gate。

## 不允许的解释

本变更只提高执行效率和可观测性，不是协议阈值调整，也不提供预测因果、稀疏非劣性或网络 MVP 的证据。首次机制运行及其 `INCONCLUSIVE` 状态永久保留。
