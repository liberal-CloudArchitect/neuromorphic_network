# T1c 结果：多情境下 GRU 更好；槽结构更能保护未切换的情境，但更新被切换的情境更差

本报告属于 T track 的探索层，不构成任何 Gate 证据。协议在运行之前已冻结并提交（`ad7f0fc`）；冻结前在非正式 seed 991 上做过两次设计检查（第一次所有模型都受预算限制，因此改为每个 episode 切换 2 次、预算 10,000 次更新），已在协议第 8 节披露。正式运行耗时 8,137 s（8 个 CPU 进程；与 T2 共享 CPU，因此比预计长）。运行期间，为 T2 给 `selector_head` 增加了类别数参数（默认值 2，行为不变）；T1c 的工作进程在启动时已载入原代码，结果不受影响。

## 2. 裁决（协议 6.1）

H1、H2 都不支持，H4、H5 都不成立：**多情境下 GRU 更好**，在恢复（−3.6pp）与 OOD 总体（−2.2pp）上都是如此。`enr_gate` 只在 2/10 个 seed 上恢复不低于 GRU（707、710）。

- 槽结构的工作记忆没有在“同时保持多个独立变量”时带来优势；T1b 在单情境下的“持平”也没有延伸到多情境。
- T1b 的写入改进在多情境下依然成立（H3 +6.9pp）：没有读出增强写入时（`cur_gate`），10 个 seed 都没有学会（恢复 0.64–0.67）。

## 3. 机制：槽结构“保护”得更好，但“更新”得更差（预注册描述）

**干扰**（另一情境切换后 1–3 个 trial 内、自身未切换的情境的准确率 − 切换前准确率，test）：

| 模型 | 均值 | 95% CI |
|---|---:|---|
| `cur_gate` | −0.002 | [−0.004, −0.001] |
| `enr_gate` | −0.004 | [−0.005, −0.003] |
| `gru` | −0.013 | [−0.014, −0.011] |

**多情境规则探针**（analysis，每个 feedback 步之后的状态，逐情境线性读出当前规则）：

| 模型 | addressed_pre | addressed_post | held_pre | held_post |
|---|---:|---:|---:|---:|
| `cur_gate` | 0.999 | 0.066 | 1.000 | 0.063 |
| `enr_gate` | 0.994 | 0.392 | 0.997 | 0.368 |
| `gru` | 0.990 | **0.543** | 0.989 | **0.519** |
| 参考（观察者集合内均匀猜） | 1.000 | 0.549 | 1.000 | 0.524 |

| 对比（held_post） | 均值 Δ | 95% CI |
|---|---:|---|
| `enr_gate` − `gru` | −0.152 | [−0.220, −0.085] |
| `enr_gate` − `cur_gate` | +0.305 | [+0.244, +0.361] |

- 切换前，三种模型的状态中都能近乎完美地读出所有情境的规则；工作记忆略好（0.994–1.000 对 0.989–0.990），行为上切换前准确率也更高（0.995–0.998 对 0.986）。
- 另一情境切换时，工作记忆几乎不受干扰（−0.2 至 −0.4pp），GRU 下降 1.3pp。**槽结构确实把不同情境分开了。**
- 但被切换的情境更新得差：切换后，GRU 的状态中能读出更新后的规则（0.52–0.54，与观察者参考水平相同），`enr_gate` 只有 0.37–0.39，`cur_gate` 几乎为 0。行为上的恢复差距（−3.6pp）与此一致。

## 4. 事后分析（未预注册）：可能的原因是门控不按情境寻址

- `working_memory.v1` 与 T1/T1b 的门控中，surprise 以每槽一个的权重 w 加到所有槽的门 logit 上：g_t = σ(W_g r_t + b + s_t·w)。它决定“这一步写不写”，但不决定“写哪个槽”。写哪个槽只能由 W_g r_t 决定。
- 在多情境中，一次意外的反馈只关于一个情境。门控把所有槽一起推向“写”，模型只能在两种代价之间权衡：要么让其他槽也被改写（干扰），要么压低门控对 surprise 的响应（更新变慢）。结果显示模型选择了后者：干扰极小，更新不足。GRU 没有这种全局的门，可以让 surprise 只改变与当前情境相关的子空间。
- 这一解释没有被本协议检验。可检验的后续：让 surprise 只作用于按内容寻址的槽，例如 g_t = σ(W_g r_t + b) ⊙ (1 + s_t·a_t)，其中 a_t 为本步读出注意力；与本次的全局门控和 GRU 比较。

## 5. 结论

1. **按预注册裁决，多情境下 GRU 优于槽结构的工作记忆**（恢复 −3.6pp、OOD −2.2pp，非劣都不成立）。T1b 中“与 GRU 持平”的结论只适用于单个变量。
2. **槽结构有真实的作用，但只在“保护”一侧**：其他情境切换时几乎不受干扰（−0.4pp 对 −1.3pp），切换前也更准确。它的弱点在“定点更新”：被切换的情境中，更新后的规则在状态里读不出来。
3. **读出增强写入在多情境下仍然必要**（H3）：没有它时，工作记忆一个 seed 都学不会。
4. 对 T-Gate 的含义：把 T1b 的工作记忆原样接入完整网络，在需要多个独立变量的任务上可能不如 GRU；接入前值得先检验按内容寻址的 surprise 门控（第 4 节）。

## 6. 解释边界

- 只有 3 个情境、4 个槽、一种任务；不是容量压力测试。
- 第 4 节是事后解释，没有被检验。
- GRU 比工作记忆多 5.5% 的参数。
