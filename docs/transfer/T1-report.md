# T1 结果：surprise 门控让主网络的工作记忆稳定地学会“从错误中发现规则切换”；但整体仍不如 shared GRU

本报告属于 T track 的探索层，不构成任何 Gate 证据。协议在运行之前已冻结并提交（`6886143`）；冻结前只在 seed 999 上用 train/validation 做过两次设计检查（已在协议中披露）。运行耗时 3,759 s（8 个 CPU 进程）。

（test 恢复准确率）

- 没有 surprise 时，主网络的工作记忆**要么学会、要么学不会**从反馈中发现切换：5/10 个 seed 达到约 0.79–0.80，另外 5/10 停在约 0.54。打乱的 surprise 同样如此。
- 有 surprise 门控时，**10/10 个 seed 都学会了**（0.74–0.80），接近理想观察者（0.80）。在 plain 也学会的 seed 上，门控没有额外提高。
- 同样的 surprise 作为输入（`input`）也有帮助，但比门控弱且不稳定（0.70–0.79）：**预测误差用来门控写入，比作为信息输入更有效**（H2），这与 F1b 以及 P5 的教训一致。

## 4. 结论

1. **迁移成立（H1–H3）**：把 F1b 的原理“预测误差门控写入”放进主网络的工作记忆，在无提示规则切换任务上使恢复准确率提高 10.9pp。门控优于同信息输入，也优于打乱的信号。它的主要作用是让学习**可靠**（10/10 对 5/10）。
2. **但相对主基线不占优（H4）**：shared GRU 在所有 seed 上都更好（OOD 总体 0.841 对 0.812，恢复 0.836 对 0.778）。可能的原因是 `working_memory.v1` 的结构：候选写入只来自当前表示，难以跨步结合 query 与反馈，而 GRU 的循环状态可以直接做这种结合。本协议无法区分这一点。
3. 对主线的含义：预测误差应当作为**写入门控信号**（而不是改写表示或调制路由）；单独改门控不足以让模块化网络超过 GRU，工作记忆本身的写入结构也需要改进。
